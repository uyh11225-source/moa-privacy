MoA 개인정보처리방침

시행일: 2026년 8월 16일 · 최종 수정: 2026년 9월 22일
문의: uyh00001@gmail.com
공개 URL: https://uyh11225-source.github.io/moa-privacy/privacy-policy.html

MoA(이하 “앱”)는 부동산 중개 업무를 위한 일정·매물·고객 정보 관리, 알림, 음성 등록, 수신전화 메모 기능을 제공합니다. 본 방침은 앱이 처리하는 정보와 이용자 권리에 대해 설명합니다.

요약: 일정·매물 등 업무 데이터는 기기에 저장되며, 로그인한 사용자에 한해 동일 계정의 일정·매물이 MoA Cloud API(클라우드 동기화 서버)로 전송·저장될 수 있습니다(백업·복원·기기 간 동기화). 로그인 없이 둘러볼 수 있으나, 일정·매물 등록, 음성 등록, 수신전화 메모 등 업무 기능은 Google 또는 네이버 로그인이 필요합니다. 로그인 시 계정·세션 정보는 MoA 인증 서버 및 Firebase Firestore에 저장됩니다. 앱은 통화 기록(CALL_LOG)과 SMS 내용을 읽지 않으며, MoA 운영 서버로 음성 원본·외부 AI 분석을 보내지 않습니다.

1. 수집·이용하는 정보

1-1. 업무 데이터(기기 저장)

다음 정보는 앱 기능 제공을 위해 사용자 기기(앱 내부 저장소)에 저장됩니다. 로그인하지 않은 상태에서 생성·수정한 데이터는 기기에만 남을 수 있습니다.

항목 이용 목적 보관 위치

매물 정보(주소, 세입자, 메모 등) 매물 등록·조회·수정·삭제 기기 내부 저장

1-2. 클라우드 동기화(로그인 사용자)

로그인한 사용자가 일정·매물을 등록·수정·삭제하면, 앱은 유효한 로그인 세션을 사용하여 MoA Cloud API와 HTTPS로 통신하며, 해당 계정에 연결된 일정·매물 레코드를 서버에 업로드·갱신· 조회할 수 있습니다. 삭제한 항목은 동기화 시 삭제 시각(tombstone) 정보가 함께 전달될 수 있습니다.

  • 동기화 대상: 일정·매물 데이터(기기에 저장된 해당 필드가 JSON 형태의 payload로 전송됨). 앱 설정·음성 원본·수신전화 메모 전용 데이터만을 별도로 동기화하는 기능은 현재 구현에 없습니다.
  • 목적: 동일 MoA 계정으로 재설치·다른 기기 로그인 시 업무 데이터 복원·일관성 유지.
  • 계정 구분: 클라우드 저장 데이터는 MoA 인증 서버가 검증한 세션의 사용자 ID에 연결됩니다. 클라이언트가 임의의 다른 사용자 ID를 지정해 저장하는 방식은 허용하지 않습니다.
  • 로그아웃: 서버에 이미 저장된 클라우드 일정·매물은 로그아웃만으로 삭제되지 않습니다.

1-3. 음성 기능 처리 방식

음성 등록 기능은 사용자가 마이크 입력을 시작할 때 동작합니다.

  • 음성 인식: 기기 또는 운영체제(OS)가 제공하는 음성 인식 기능을 사용합니다.
  • 일정·매물 파싱: 인식된 텍스트는 앱 내부의 로컬 파서에서 처리되어 일정·매물 정보로 변환됩니다.
  • MoA 서버: 음성 원본 파일·음성 인식 결과 자체를 MoA 인증 서버나 MoA Cloud API로 전송하지 않습니다. 음성으로 생성된 일정·매물은 일반 업무 데이터와 같이 기기에 저장되며, 로그인 사용자는 위 1-2에 따라 클라우드 동기화될 수 있습니다.
  • OS 음성 인식 서비스: 기기·OS 음성 인식 기능을 사용하는 경우, 해당 기능의 처리 방식에는 기기 제조사·OS·음성 인식 서비스 제공자의 정책이 적용될 수 있습니다.

1-4. 로그인 계정 데이터(인증 서버·Firestore)

Google 또는 네이버 로그인은 업무 기능을 사용하기 위해 필요합니다. 로그인하지 않아도 앱 화면을 둘러볼 수 있으나, 일정·매물·고객 등록, 음성 등록, 수신전화 메모 설정 등 실제 업무 기능을 사용하려면 로그인이 필요합니다.

로그인을 이용하면 아래 정보가 MoA 인증 서버 및 Firebase Firestore에 저장될 수 있습니다.

1-5. 무료 사용(체험) 중복 방지 기록(Trial identity ledger)

동일 Google 또는 네이버 로그인 계정으로 무료 사용 기간을 반복 받지 않도록, MoA 인증 서버(Firebase Firestore)에 제한된 Trial 사용 기록을 저장할 수 있습니다. 현재 구현에서 이 기록에는 다음이 포함됩니다.

  • 문서 식별자: 소셜 로그인 제공자와 제공자 사용자 식별자를 서버 전용 비밀값으로 HMAC-SHA256 처리한 결과(원문 provider 사용자 ID·이메일· 이름·전화번호·토큰은 ledger 문서 필드에 저장하지 않음)
  • 필드: trialConsumed, firstTrialStartedAt, firstTrialEndedAt, createdAt, updatedAt

회원 탈퇴 시 MoA 사용자 계정·소셜 연결·세션 등은 삭제되지만, 위 Trial identity ledger 기록은 중복 무료 사용 방지 목적으로 유지될 수 있습니다.

2. 기기 권한

앱이 실제로 선언·사용하는 주요 권한은 다음과 같습니다.

  • 인터넷: 로그인, 클라우드 동기화, 앱 업데이트 확인 등
  • 알림(POST_NOTIFICATIONS): 일정 알림 및 수신전화 메모 알림 표시
  • 마이크(RECORD_AUDIO): 음성으로 일정·매물 등록(사용자가 음성 입력을 시작할 때)
  • 오디오 설정(MODIFY_AUDIO_SETTINGS): 음성 입력·알림음 재생을 위한 오디오 설정
  • 전화 상태(READ_PHONE_STATE): 수신전화 메모 사용 시 통화 종료 후 알림을 정리하기 위해 사용합니다. 통화 기록(CALL_LOG)은 읽지 않습니다.
  • 연락처(READ_CONTACTS, 선택): 수신전화 메모(Call Screening) 기능과 관련하여 Android가 요구할 수 있는 권한입니다. 앱은 연락처 데이터베이스를 조회해 목록을 수집·저장하거나 서버로 전송하지 않습니다. 수신전화 메모는 앱에 등록된 일정/매물 전화번호와 발신번호를 기기 안에서 대조합니다.
  • 발신자 확인(Call Screening) 역할(선택): 등록된 번호로 전화가 왔을 때 관련 일정·메모를 표시합니다. 통화를 차단하거나 스팸 판별에 사용하지 않습니다.
  • 전체 화면 알림(USE_FULL_SCREEN_INTENT): 잠금 화면에서 일정 알림·수신전화 메모 표시
  • 포그라운드 서비스: 수신전화 메모 등 짧은 백그라운드 처리
  • 진동·깨우기(WAKE_LOCK 등): 알림 표시를 위한 시스템 권한

수신전화 메모, 연락처·전화 상태 권한, Call Screening 역할은 선택 기능입니다. 허용하지 않아도 일정·매물 등록 등 다른 업무 기능을 사용할 수 있습니다(해당 기능 사용 시 로그인은 필요합니다).

3. 읽지 않는 정보

  • 통화 기록(통화목록) — 앱은 READ_CALL_LOG 권한을 선언·사용하지 않습니다.
  • SMS·문자 메시지 내용 — 앱은 READ_SMS 권한을 선언·사용하지 않습니다.
  • 연락처 목록 전체(이름·번호 목록을 수집·저장·전송하지 않음)
  • 위치 정보

4. 수신전화 메모

수신전화 메모는 사용자가 기능을 켠 경우에만 동작합니다. 앱에 저장된 일정·매물의 전화번호와 수신 발신번호를 기기 안에서 대조하고, 일치하면 관련 메모·일정 요약을 알림 또는 오버레이로 표시합니다. 이 과정에서 사용하는 발신번호와 대조 정보는 기기 내부에서 처리되며 MoA Cloud API로 전송하지 않습니다(일정·매물에 포함된 번호가 클라우드에 동기화되는 것은 1-2와 같습니다).

5. 제3자 서비스 및 외부 연동

앱은 이용자의 일정·매물 데이터를 제3자에게 판매하지 않습니다. MoA 인증·클라우드 동기화·로그인 운영을 위해 다음 외부 서비스를 이용할 수 있습니다.

  • Google: Google 로그인 인증
  • 네이버: 네이버 로그인 인증 및(회원 탈퇴 시) 연동 해제
  • Firebase Firestore(Google): 로그인 계정·세션·Trial identity ledger 등 인증 관련 정보 저장
  • MoA Cloud API: 로그인 사용자의 일정·매물 클라우드 동기화(운영자가 관리하는 동기화 서버)
  • Expo Updates: 앱 업데이트 배포 확인(업무 데이터 전송 목적 아님)

사용자가 전화·문자·메일 앱을 직접 실행하는 경우 해당 OS·앱의 정책이 적용됩니다. 기기·OS 음성 인식 기능을 사용하는 경우 해당 서비스 제공자의 정책이 적용될 수 있습니다. 서비스 제공 과정에서 국외 서버에서 계정·동기화 데이터가 처리될 수 있습니다. 클라우드·인증 인프라의 처리위탁·국외 이전에 관한 법적 표시는 운영 정책 및 관계 법령에 따라 별도로 확인·고지될 수 있습니다.

6. 보관 기간 및 파기

  • 로컬 업무 데이터: 사용자가 앱에서 해당 항목을 삭제하거나, 기기 설정에서 앱 데이터를 삭제하거나, 앱을 제거할 때까지 기기에 보관됩니다.
  • 클라우드 일정·매물: 로그인 사용자의 동기화 데이터는 MoA Cloud API에 보관되며, 회원 탈퇴 시 해당 계정에 연결된 일정·매물 서버 데이터 삭제를 시도합니다.
  • 로그인 계정 정보: 서버의 사용자·소셜 계정·세션 등은 회원 탈퇴 시 삭제합니다. 로그인 세션은 로그아웃, 회원 탈퇴 또는 유효기간 만료 시 삭제됩니다.
  • 로그아웃: 서버 세션을 종료하고 기기의 로그인 상태만 제거합니다. 로컬 일정·매물·고객·메모 등 업무 데이터와 클라우드에 저장된 동기화 데이터는 로그아웃만으로 삭제하지 않습니다.
  • 회원 탈퇴: 앱에서 회원 탈퇴를 완료하면, 구현된 순서에 따라 먼저 MoA Cloud API에 저장된 해당 계정의 일정·매물 데이터 삭제를 요청하고, 그 요청이 성공한 경우 MoA 인증 서버(Firestore)의 사용자 계정, 소셜 계정 연결, 세션, 저장된 네이버 연동 해제용 토큰(해당 시)을 삭제합니다. 클라우드 삭제에 실패하면 회원 탈퇴 처리가 완료되지 않을 수 있습니다. Google 계정 자체나 네이버 계정 자체를 삭제하지 않으며, 네이버의 경우 가능하면 연동 해제를 시도합니다. 회원 탈퇴 시에도 이 기기에 저장된 일정·매물·고객·메모 등 업무 데이터는 자동 삭제하지 않습니다. Trial identity ledger(1-5)는 중복 무료 사용 방지를 위해 삭제하지 않을 수 있습니다.
